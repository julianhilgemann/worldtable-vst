# T3.2 — Harmony: chord hold, scales and MIDI latch
**Milestone:** M3   **Depends on:** T3.1   **Branch:** feat/t3.2-harmony

## Goal
The chord the instrument holds: port the T1.3 sketch's chord vocabulary and naming
(`prototype/sky/sound/harmony.js`), and add what the sketch left out and the spec asks
for — chord hold (root, Mood, chord shape), the six scales, MIDI latch, and
Transpose/Register. Prove it with unit tests; let `WorldtableRender --sky` play any held
chord. The sky-driven progression is T3.3.

## Design
- **Vocabulary** (`dsp/Harmony.h/.cpp`): the sketch's `VOCABULARY` line by line — three
  Moods (bright, bittersweet, nocturnal) × four functions (home, tension, awe, borrowed)
  × two or three chords. `Mood`, `ChordFunction`, `ChordShape { degree, intervals,
  name }`, `chordOf (mood, function, index, key)`; an out-of-range index clamps, so the
  progression (T3.3) cannot ask for a chord that doesn't exist.
- **Naming** (the sketch's `chordName`): spelled label (`B♭maj7`) and roman numeral
  (`♭VI`) in fixed `char` buffers — no `std::string` on the audio thread. The shape name
  is derived from the intervals, so a latched chord gets a name too. The first chord of
  `spec/05` §12's vocabulary (`D maj7`, `B♭maj7`, `Gm add9`) must come out as the golden
  and the UI show them.
- **Scales** (spec/01 §4, spec/05 §3): major, Lydian, major pentatonic, minor, Dorian,
  minor pentatonic; intervals, `inScale`, `snapToScale`. They do not tune the bank — the
  layers play chord tones (`spec/05` §1) — but the sparkles (T3.4) and the progression's
  scale-tone step (T3.3) need one shared definition. Defined and tested here, unused by
  the audio path until then.
- **Chord hold** (`dsp::Harmony`): key, Mood, function, chord index, Transpose, Scale.
  `chord()` is the sounding chord; Transpose shifts the key, so all three layers follow.
  `poll (out)` reports a changed chord once (the host turns that into
  `SkySound::requestChord`). `register` and `spread` stay `SkySound::Settings` (T3.1).
  The setters are atomic and the class never allocates, so T3.3 can own it on the audio
  thread; `poll` and the MIDI calls are audio-thread only.
- **MIDI latch** (spec/01 §4: "notes held → chord"): a note-on is
  latched immediately from the held notes; the root is the lowest held note that spells
  a known shape (so an inversion still reads as its root), otherwise the lowest note. Pitch
  classes are deduplicated, the five lowest are kept (`Chord::kMaxTones`), and the intervals
  are pitch-class intervals (0–11) so a latched `C E G D` is `Cadd9`. **Changed in T3.6
  (owner decision):** the last note-off clears the latch and the sky resumes (see T3.6 and
  spec/05 §3); T3.2 originally kept the last chord until a chord control cleared it. Chord controls (key, Mood, function, shape) clear the latch, so the
  next note-on takes over again; Transpose applies to a latched chord too. A strum inside
  one 10 ms tick is one request (the host polls per tick); a slower strum may ask twice —
  the double-banked bank replaces a pending request, so nothing clicks.
- **Render** (`WorldtableRender --sky`): `--mood`, `--root`, `--chord`,
  `--transpose`, `--register`, `--spread`; the tool holds that chord and prints its label
  and roman numeral.

## Constraints
- Rule 1: `Harmony` doesn't allocate, lock or log; all buffers are fixed.
- Rule 4: a chord change is a `Chord` for `SkySound`, which already double-banks and
  crossfades; Harmony itself never produces a jump. Transpose is a chord change like any
  other (the old bank rings out).
- Rule 5: `chord()` is a pure function of the settings and the held notes — no time,
  no randomness.
- 12-TET only (`spec/01` §4); no microtonal notes.

## Notes
- **Vocabulary:** 35 chords — bright 12, bittersweet 11, nocturnal 12. Every `degree`,
  interval and shape name matches `harmony.js`; the test walks all of them. An index past
  the end clamps to the function's last chord, so T3.3 cannot ask for one that isn't there.
- **Naming:** all 35 labels match the sketch's `chordName` (the test checks the derived
  label ends with the sketch's shape name, and the golden's three chords exactly:
  `Dmaj7`/`I`, `B♭maj7`/`♭VI`, `Gm add9`/`iv`). The shape comes from the intervals, so a
  latched `C E G` is `Cmaj`; an unknown set gets the shape `alt` (e.g. `Calt`) with the
  right root and roman numeral, rather than a wrong conventional name.
- **Hold:** `Harmony` owns key/Mood/function/chord index/Transpose/Scale behind atomics;
  `chord()` is pure. Transpose shifts the key (so all three layers follow); Register and
  Voicing spread stay `SkySound::Settings`, as T3.1 left them. A chord control clears the
  MIDI latch.
- **Latch:** the root is the lowest held note that spells a known shape — so `E G C`
  reads `Cmaj`, not an E-rooted cluster — otherwise the lowest note. Pitch classes are
  deduplicated and the five lowest are kept (`Chord::kMaxTones`); intervals are
  pitch-class intervals, so `C E G B♭ D` is `C9`. Releasing one tone re-latches only if
  the remaining set is still a known shape (so `C E G B♭` → `C E G` gives `Cmaj`); dropping
  to a shape-less subset keeps the last chord. All notes off keeps it. A note-on is
  latched at once; the host polls per tick, so a strum inside one 10 ms tick is one request.
- **Scales:** the six tables are in and tested (`inScale`, `snapToScale`, ties up); nothing
  in the audio path calls them yet — they are for T3.4's sparkles and T3.3's scale-tone
  step, as the task says.
- **Render** (Debug build, so the CPU line isn't meaningful): 60 s of the 10 May 2024 storm
  from 17:20 UT at 24×, held `B♭add9` (bright, root B♭, chord 1), stand-in effects:
  peak −1.0 dBFS, RMS −18.4 dBFS, max step 0.048, no NaN/inf, 0 resets, 1 onset. The
  quiet dry run (`--mood nocturnal --root C --chord 2 --transpose 2` → `Dm11`, roman `i`)
  was also clean. For an ear check:
  `build/dev/WorldtableRender_artefacts/Debug/WorldtableRender --sky --from 17:20 --seconds 60 --mood bright --root Bb --chord 1 --out renders/T3.2-bbadd9.wav`.
- **Checks:** ctest 72/72 (134 s, 8 new Harmony cases with 537 assertions); AU, VST3 and
  Standalone build with no new warnings; `pluginval --strictness-level 8` SUCCESS; the
  sketch's 15/15 tests are unchanged.
- **No change to the sound:** `SkySound`, `ResonatorBank`, `Exciter`, `Voicing` and the
  T3.1 sound golden are untouched; `ctest` still matches the sketch exactly.

## Open questions (owner)
- **Scales vs the vocabulary.** The sketch's chords are fixed interval sets per Mood, so
  the scale currently has no say in the bank's tuning; it is defined for the sparkles and
  the progression's step. Should a scale instead filter or reshape the vocabulary (the POC
  built chords from scale degrees), or is Mood the only chord-shape control?
- **"Chord shape" control.** T3.2 reads it as the index within the current function
  (maj7 / add9 / 6/9 for bright home, and so on), which is what the sketch's progression
  picks from. Is that what the UI's chord control should be?
