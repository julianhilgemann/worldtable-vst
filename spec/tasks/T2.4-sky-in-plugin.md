# T2.4 — The Sky Model in the plug-in
**Milestone:** M2   **Depends on:** T2.3, T2.5, ADR-0003 (accepted 2026-11-05)
**Branch:** feat/t2.4-sky-in-plugin

## Goal
Run the C++ Sky Model inside `processBlock` on the 100 Hz sample grid
(ADR-0007), feed it a storm day through the track hand-off, and give the UI
(and later OSC) its frames and events through the hand-offs of ADR-0003.
M2's "See" line: the existing UI shows the replayed storm. The sound doesn't
change yet (M3).

## Design
- **Hand-offs (ADR-0003):**
  - `dsp/SlotExchange.h`: `TableExchange` becomes `SlotExchange<T, N>`, same
    code; `TableExchange` is now `SlotExchange<WavetableSet, 4>`.
  - `sky/SkyHandoff.h`: `TripleBuffer<T>` (one writer, one reader, newest
    wins, wait-free) and `SkyEventFifo` (single-producer, single-consumer,
    256 events, counts drops).
- **`sky/SkyRuntime`** (audio side): owns the `SkyModel`, the `SkyClock`, the
  track pool (`SlotExchange<TrackBundle, 3>`, a bundle = `WorldSnapshot` +
  `SkyTimeline`) and one triple buffer and one event FIFO per reader (UI,
  OSC). `process(numSamples)`: take a published bundle at block start, apply
  speed and seek requests (atomics), step the model at every tick inside the
  block, publish each tick's snapshot and events.
- **`sky/SkyFeed`** (data side): builds a bundle from a bundled storm day into a
  free slot and publishes it. For M2 it runs once, synchronously, when the
  plug-in is created (like `WorldFeed::prime`): 10–11 May 2024, seed 1,
  default params, Journey at 24× from the start of the day. Day choice, Live
  and a background thread come with M5; speed and seed parameters with M4/M6.
- **`data/SkyDays`**: the three recorded days in `resources/sky/` are bundled
  into the binary (`WorldtableSkyData`, about 315 KB); `loadBundledDay()`
  parses one into a `RawTrack`.
- **Editor:** the 30 Hz telemetry gains a `sky` object (model time, phase,
  progress, Kp, Bz, wind, energy, activity, unloading, onsets, last onset, MLT,
  arc latitude, speed) and the onsets since the last frame. The web UI shows
  one readout line under the status line. The browser mock leaves it hidden.

## Scope
The files above; `PluginProcessor` (owns `SkyRuntime` and `SkyFeed`, calls
`process` in `processBlock`); `PluginEditor` (telemetry); `source/ui/`
(readout); `CMakeLists.txt` (binary data, sources); tests.

## Out of scope
Sound from the sky (M3), OSC output (M5), parameters for speed, seed or day
(M4/M6), saving the sky with the session (M6), Live data (M5).

## Notes
- **Determinism:** 3,000 ticks at 1440× (12 h of the storm from 17:30 UT,
  with onsets, phase changes and whistlers) in blocks of 4800, 128, 37,
  alternating 1/4799 and random 1–2000 samples: identical snapshots and
  events. 44.1 kHz and 48 kHz give the same sky for the same ticks.
- **Requests take effect at block start.** `setSpeed` and `seek` from other
  threads are applied when the next block begins, so their tick depends on the
  host's block size. The same requests at the same ticks give the same sky.
- **Changing days:** `SkyFeed::load` then `SkyRuntime::seek` to the new day's
  start. A new track with the same seed and params keeps the slow state
  (the reviewed `setTimeline` rule, meant for Live updates), so a day change
  needs the seek. The test walks all three bundled days through the pool of
  three slots without allocating on the audio thread.
- **Real UI** (`WorldtableUICheck`, the editor in a real WebView): the readout
  shows `10 May 00:00 UT · quiet · Kp 2.7 · 0 onsets · 24×`. The tool now
  checks it.
- The plug-in builds the storm day's timeline when it is created (about 130 ms
  in Debug), like `WorldFeed::prime`. The Journey starts at 10 May 00:00 UT,
  runs 2 h of real time for the 48 h day, then holds at the end.
- `TableExchange` is now `SlotExchange<WavetableSet, 4>`; its existing tests
  and the render tests pass unchanged.
- The bundled days add about 315 KB to the binary (`WorldtableSkyData`).
- **Test hygiene:** a test that creates a `PluginProcessor` needs
  `juce::ScopedJuceInitialiser_GUI` (the world feed uses timers).
