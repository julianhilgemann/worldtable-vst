## Notes

### Building locally
```sh
cmake --preset dev && cmake --build --preset dev && ctest --preset dev
pluginval --strictness-level 8 --validate <build>/Worldtable_artefacts/Debug/VST3/Worldtable.vst3
```
Add `-DWORLDTABLE_COPY_PLUGINS=ON` to install into `~/Library/Audio/Plug-Ins`
after each build (needed for AU: auval / DAWs only see registered components).

**Paths with shell metacharacters.** JUCE 8's post-build commands (VST3
`moduleinfo.json`, copy, ad-hoc signing) use `add_custom_command` without
`VERBATIM`, so CMake escapes spaces but not `&`. A build dir under e.g.
`Files & Data/` fails with `/bin/sh: Data/...: No such file or directory`.
`CMakeLists.txt` now fails fast with a clear message. Fix: keep the build dir
on a clean path (the owner renamed the folder to `files/`, so the in-repo
`dev` preset works as is). Otherwise, use a git-ignored `CMakeUserPresets.json`
whose presets inherit `dev` and set `binaryDir` outside the repo.

### Testing without a DAW
- **AudioPluginHost (JUCE extras):** `tools/host/run_host.sh` builds the host
  from the pinned JUCE source on first run (into `build/tools/`) and opens
  `tools/host/Worldtable-AU.filtergraph`: on-screen keyboard -> MIDI Input ->
  Worldtable (AU) -> Audio Output, plus the built-in MIDI Logger to show MIDI
  flowing. Click keys, or focus the keyboard and type (A W S E D ...). Needs
  the AU installed (`-DWORLDTABLE_COPY_PLUGINS=ON`). Swap in a VST3 by
  dragging `Worldtable.vst3` onto the graph.
- **Standalone app:** `build/dev/Worldtable_artefacts/Debug/Standalone/Worldtable.app`.
  Options -> Audio/MIDI Settings picks the output and MIDI input (hardware or
  IAC bus). It has no on-screen keyboard.
- **Headless:** ctest + pluginval + auval now; `tools/render_offline` (T1.5)
  will render fixture worlds to WAV for NaN/click/loudness checks.
- M0 is silent by design: these checks prove loading, MIDI routing, editor
  and state, not sound. First audible output comes in M1 (T1.1/T1.2).

### Implementation notes
- `WorldtableShared` (INTERFACE target) carries sources, JUCE modules and flags;
  both the plugin and `WorldtableTests` link it, so tests compile exactly the
  plugin's code. The test exe is a `juce_add_console_app` + `Catch2WithMain`.
- JUCE 8.0.17 splits `AudioProcessor` into `juce_audio_processors_headless` —
  candidate for GUI-free DSP test targets later.
- CI uses the default generators (Makefiles on macOS, VS 2026 on
  windows-2025) rather than Ninja, so the multi-config path is exercised too.
  Windows has not been built yet.
