# T2.1 — Sky Model interfaces (header-first)
**Milestone:** M2   **Depends on:** T1.2   **Branch:** feat/t2.1-sky-interfaces

## Goal
Fix the two hand-offs around the C++ Sky Model before any of it is built:
what goes in (`WorldSnapshot`, a data track) and what comes out (`SkySnapshot`,
the sky after one tick), and the `SkyModel` class between them. Headers and
compile-time checks only, for the owner's review (`spec/08` loop, step 2).
T2.2–T2.5 implement them and must match the T1.2 goldens.

## Design
- **Mirror the sketch.** Fields, units and behaviour follow
  `prototype/sky/model.js`, so T2.2–T2.5 can port it line by line.
  `SkyParams` is the sketch's `DEFAULTS` with the same names and values (the
  goldens store them, and a test checks that they agree).
- **WorldSnapshot** (`spec/03` §A): 6 channels on a 1-minute grid, 72 h capacity,
  `float`, with gaps already filled by the data thread and `valid` flags for
  measured samples. Channel 0 is H minus the station's quiet level, so the data
  thread owns the baseline (the sketch's `quietBaseline`; Live needs a rolling
  one). Inline `sample()` is the sketch's linear interpolation.
- **SkySnapshot** (`spec/03` §B plus the fields `spec/04` §10 asked for): a
  fixed-size POD of 4.8 KB (4,824 B) at 128 nodes. Per node: displacement, velocity,
  brightness, green/red/violet, geomagnetic latitude and longitude, pulse. The
  oval edges, gain, unloading, coupling, ΔH measured and modelled, MLT, storm
  red, the last onset (time, strength, node, kind, ΔH/5 min), the last whistler,
  sun and moon, and the observer (station, dipole pole, magnetic zenith). A
  renderer or OSC needs nothing else.
- **SkyModel** (audio thread, ADR-0007): `step()` is one 100 Hz tick and
  returns that tick's events as a span. Speed is capped at 1440×, so at most
  15 slow steps run per tick and the event buffer can't overflow. `current()`
  is the snapshot after the last step: the sound reads it directly, while the
  UI and OSC get published copies (ADR-0003). `SkyClock` puts tick k on sample
  `round(k × sampleRate / 100)`, as the sketch's engine does, so the grid
  doesn't depend on block size.
- **Seeking without hours of replay.** On a cold seek the sketch replays the
  slow sky from the track start: up to 259,200 slow steps for a 72 h track.
  That is fine in a browser but an unbounded loop on the audio thread. Here a
  **`SkyTimeline`** holds the slow state at every model minute for one track,
  seed and parameter set: 2,881 states of 248 B (≈ 0.7 MB) for a 48 h day.
  The data thread builds it in about 0.2 s (estimate) and publishes it with the
  track. `seek()` copies one checkpoint and replays at most 59 slow steps. The
  same table gives Live its state at "now", the goldens their per-minute trace
  and the UI its day chart (phases and onsets).
- **`SlowSkyState` is a POD** (the sketch's `initialSlow` fields), so a
  checkpoint is a plain copy and a frozen sky can be saved with the session
  (`spec/03`, State & persistence). Field names are readable, with the sketch's
  short names in comments.
- **Freeze = speed 0.** Model time and data hold; the curtain keeps moving on
  real time. This is the `spec/01` §3 proposal, still open there.

## Scope
- `source/data/WorldSnapshot.h`: track POD, `StationId`, inline `sample()` and
  `validAt()`.
- `source/sky/SkySnapshot.h`: output POD.
- `source/sky/SkyParams.h`: tuning constants (the sketch's `DEFAULTS`) and the
  dipole pole.
- `source/sky/SkyModel.h`: `SkyEvent`, `SlowSkyState`, `SkyTimeline`, `SkyModel`,
  `SkyClock` (inline).
- `tests/unit/SkyInterfaceTests.cpp`: layout checks, `SkyClock` grid,
  `WorldSnapshot::sample`, `SkyParams` == the goldens' params.
- `spec/03-architecture.md` §A/§B point to the headers; `spec/04` §10 marked done.

## Out of scope
Any implementation of `SkyModel` or `SkyTimeline` (T2.2–T2.5), the hand-off
mechanism (triple buffer vs atomic pointer, ADR-0003), `TrackBuilder` (M5),
saving the frozen sky (M6).

## Tests for T2.2–T2.5 (written there, against these headers)
- Determinism: same seed, timeline and sample rate give an identical snapshot
  sequence for blocks of 4800, 128 and 37 samples.
- The slow sky at 6× and 96× is bit-identical to `SkyTimeline` minute states.
- Goldens (10 May 2024, seed 1): slow channels within tolerance, onset times
  within ±1 min, node brightness and displacement statistics.
- Seek round-trip; at most 59 slow steps per seek; at most `kMaxEventsPerStep`
  events per tick at 1440×.
- `step()` doesn't allocate (counting `operator new` in the test).

## Notes
- Measured sizes: `SkySnapshot` 4,824 B, `SlowSkyState` 248 B, `WorldSnapshot`
  129,640 B. A test pins the first two, so a layout change can't slip through.
- The plug-in build doesn't include the new headers yet; only the test target
  compiles them. `SkyModel` and `SkyTimeline` are declared, not defined: T2.2 adds
  `SkyModel.cpp`.
- Differences from the sketch's snapshot: Journey speed is `speed` and solar-wind
  speed is `windSpeedKmS` (`spec/03` §B used `speed` for both). `pulsation[2]`
  became `pcPhase` + `recoveryPulse`, with the per-node pulse in `CurtainNode`.
  The onset event also carries the onset node; the sketch's sound engine read it
  from `model.slow`.
- `WorldSnapshot` stores `float` (as `spec/03` §A had it); the sketch uses
  doubles. The goldens are matched within tolerance, not bit for bit.

## Open questions (owner)
1. **Header review:** fields, names and units in `SkySnapshot.h` and
   `WorldSnapshot.h`, both protected interfaces (`CLAUDE.md` rule 6).
2. **SkyTimeline** (above): seeks start from per-minute checkpoints built off the
   audio thread. One consequence: a seed or tuning change reaches the sky after
   the table is rebuilt (about 0.2 s), not instantly. OK?
3. **Speed cap 1440×** (24 h per real minute). Journey speeds are still open
   (`spec/01` §3); the cap sizes the event buffer.
4. **ADR-0007 is still "proposed".** T2.1 builds on it (the audio thread steps
   the model). Accept it?
5. **ADR-0003** (snapshot hand-off, triple buffer preferred) isn't written. It's
   needed by T2.4 at the latest. May I draft it?
