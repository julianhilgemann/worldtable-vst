# T6.13 — Sizes, the context menu, the welcome tour
**Milestone:** M6   **Depends on:** T6.8   **Branch:** feat/t6.13-sizes-menu-tour
**Status:** draft, start when the owner says so.   **Read first:** `spec/09-ui-v2.md` §3, §5; mockup bottom bar, right-click menu, Tour

Owner, 2026-11-13: "If i right click I want to choose between small, medium and large to scale
between sizes. default should be medium"; "a welcome, or learning menu which essentially is a popup
that walks me through how the plugin works."

## Goal
Three window sizes chosen from a right-click menu (and from the bottom bar), a context menu on
every knob, and a five-step tour shown once that can be reopened.

## Design
- **Sizes:** Small 85 % (1148 × 765), Medium 100 % (1350 × 900), Large 125 % (1688 × 1125), the
  same page scaled (as `rescale()` does today). The editor stops being freely resizable: native
  function `setUiSize(0|1|2)` → `setSize` in `PluginEditor`. The choice is a **per-computer**
  setting, not session state: a `juce::PropertiesFile` in the user's application-data folder
  (`Worldtable.settings`, key `uiSize`), read when an editor opens. Default Medium; if the
  display's usable area is smaller than Medium plus 80 px, open Small. Message thread only.
- **Context menu** (the page draws it; suppress the web view's own menu with `preventDefault` on
  `contextmenu`, and check in the real editor that WebKit's Reload/Inspect menu never shows):
  - on the background or a panel: Small, Medium, Large (a tick on the current one), Welcome tour,
    About Worldtable (version, licence, credits: the Data module's sources);
  - on a knob or handle: Reset to default, Enter value…, and its hint as a first, dimmed line.
    (T4.2 adds "Modulate with ▸".)
  Escape, a click outside or choosing an item closes it. It never opens outside the window:
  clamp to the stage. Everything in it is also reachable without a right-click: sizes and Tour in
  the bottom bar, reset by double-click, value entry by Enter (T6.7).
- **Welcome tour:** five steps, each a spotlight on a real region with a card beside it (title,
  two sentences, "Skip tour", "Next"/"Done", "Step n of 5"). Texts as in the mockup (`TOUR`):
  the day strip, the dome, Harmony, the sound chain, the macros. The page stays live under it;
  the spotlighted region stays usable, so the step's "try it" works. Shown automatically once per
  computer, 1.5 s after the first editor opens (`tourSeen` in the same settings file, set when it
  is finished or skipped). Reopened from the bottom bar and the context menu. Escape skips. With
  reduced motion the spotlight cuts instead of gliding.
  WebKit: the spotlight and the card sit over the dome's WebGL canvas: give them their own
  compositing layer (`transform: translateZ(0)`), as the View button has.
- **Mock:** sizes scale the stage in the browser; the settings live in `localStorage`.

## Acceptance criteria
- [ ] Each size opens crisp (canvases re-fit; check sizes with `--eval`), in the Standalone and in one host; the choice survives closing the editor, the host and a new instance.
- [ ] No text under 10 px on screen at Small (12 px words × 0.85).
- [ ] Right-click anywhere shows only the page's menu, never the web view's; it works over the dome.
- [ ] The tour shows once on a clean settings file, not again; Skip and Escape end it; all five spotlights land on their regions at all three sizes; it paints over the dome in the real editor.
- [ ] `UiCheck` covers: set each size, open and close the menu, run the tour to the end.
- [ ] Build without warnings, ctest green, UiCheck, pluginval 8; screenshots of the three sizes, the two menus and each tour step.
