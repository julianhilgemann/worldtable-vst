# T6.13 — Sizes, the context menu, the welcome tour
**Milestone:** M6   **Depends on:** T6.8   **Branch:** feat/t6.13-sizes-menu-tour
**Status:** approved by the owner, 2026-11-13.   **Read first:** `spec/09-ui-v2.md` §3, §5; mockup bottom bar, right-click menu, Tour

Owner, 2026-11-13: "If i right click I want to choose between small, medium and large to scale
between sizes. default should be medium"; "a welcome, or learning menu which essentially is a popup
that walks me through how the plugin works."

## Goal
Three window sizes chosen from a right-click menu (and from the bottom bar), a context menu on
every knob, and a five-step tour shown once that can be reopened.

## Design
- **Sizes:** Small 85 % (1148 × 765), Medium 100 % (1350 × 900), Large 125 % (1688 × 1125), the
  same page scaled (as `rescale()` does today). The editor stops being freely resizable: native
  function `setUiSize(0|1|2)` → `setSize` in `PluginEditor`. The choice is a **per-computer**
  setting, not session state: a `juce::PropertiesFile` in the user's application-data folder
  (`Worldtable.settings`, key `uiSize`), read when an editor opens. Default Medium; if the
  display's usable area is smaller than Medium plus 80 px, open Small. Message thread only.
- **Context menu** (the page draws it; suppress the web view's own menu with `preventDefault` on
  `contextmenu`, and check in the real editor that WebKit's Reload/Inspect menu never shows):
  - on the background or a panel: Small, Medium, Large (a tick on the current one), Welcome tour,
    About Worldtable (version, licence, credits: the Data module's sources);
  - on a knob or handle: Reset to default, Enter value…, and its hint as a first, dimmed line.
    (T4.2 adds "Modulate with ▸".)
  Escape, a click outside or choosing an item closes it. It never opens outside the window:
  clamp to the stage. Everything in it is also reachable without a right-click: sizes and Tour in
  the bottom bar, reset by double-click, value entry by Enter (T6.7).
- **Welcome tour:** five steps, each a spotlight on a real region with a card beside it (title,
  two sentences, "Skip tour", "Next"/"Done", "Step n of 5"). Texts as in the mockup (`TOUR`):
  the day strip, the dome, Harmony, the left column (resonators and EQ), the motion block (macros,
  LFO, envelope; until T4.2 the macros alone). The page stays live under it;
  the spotlighted region stays usable, so the step's "try it" works. Shown automatically once per
  computer, 1.5 s after the first editor opens (`tourSeen` in the same settings file, set when it
  is finished or skipped). Reopened from the bottom bar and the context menu. Escape skips. With
  reduced motion the spotlight cuts instead of gliding.
  WebKit: the spotlight and the card sit over the dome's WebGL canvas: give them their own
  compositing layer (`transform: translateZ(0)`), as the View button has.
- **Mock:** sizes scale the stage in the browser; the settings live in `localStorage`.

## Notes / open questions
Done 2026-11-13 (agent).

**What changed**
- **Sizes** (`PluginEditor.*`): `UiSettings` (in `PluginEditor.h`) owns the per-computer settings, a
  `juce::PropertiesFile` at `~/Library/Application Support/Worldtable/Worldtable.settings` (XML; keys
  `uiSize` 0/1/2, `tourSeen`), read and written on every call so each new editor sees the latest. (The
  Standalone's audio settings are JUCE's own `~/Library/Application Support/Worldtable.settings`, another
  file.) `$WORLDTABLE_SETTINGS_FILE` replaces the path: the UI check uses a fresh file in the temp folder
  unless the variable is set, so test runs never touch the real one. The editor is no longer resizable;
  it opens at the saved size, else Medium, or Small when the usable area of the display under the
  pointer is smaller than Medium + 80 px (this Mac's built-in 1440 × 875 gets Small, the 1920 × 1080
  display Medium). Native functions: `getUiSettings` → `{ size, tourSeen, version, wrapper }`,
  `setUiSize(i)` (resizes after the call returns, saves), `setTourSeen()`. The page keeps scaling to
  the window (`app.js rescale`, now `UI.rescale`); in the mock `UI.sizeFactor` caps the zoom and the
  choice lives in `localStorage`.
- **Bottom bar**: `#tour-btn` (chip) and `#size-seg` (S M L, a radiogroup with arrows that step without
  wrapping, Home/End) after the Details chip, as in the mockup minus Modulation.
- **Context menu** (`menu.js`): `contextmenu` is prevented on the whole document. On a `[data-param]`
  element: its hint (dimmed), Reset to default (with the default's text) and Enter value…, both sent to
  the control as the keyboard would (Backspace, Enter: `09` §5), so a knob, a handle, a picture's proxy
  (a crossover stays between its neighbours) and T6.11's value chips each take their own path. On
  anything else: Small / Medium / Large (✓ on the current), Welcome tour, About Worldtable. Clamped 6 px
  inside the stage; Escape, a press outside, a choice, a resize or the window losing focus closes it;
  arrows move in it; Shift+F10 opens it for the focused control.
  **My call:** a choice, a switch or a value chip (a button that steps) gets the control menu without
  Enter value: Enter opens no value field there.
- **About** (`#about`): version (and the wrapper's name in a host), the vision's sentence, the data
  sources with their licences (`02-data-sources.md`), the fonts' OFL, JUCE, and "open source; the licence
  is set before the first release" (there is no LICENSE file yet: **owner to choose**).
- **Tour** (`tour.js`): five steps on `#strip`, `#dome-wrap`, `#harmony`, `#col-left`, `#macros` (each step
  takes a list of ids, the spotlight is their union + 3 px). Card under the region when it fits, else over
  it, centred, inside the stage (the mockup's rule). One stage-sized `#tour-dim` layer (pointer-events
  none, so the page stays live) clips the spotlight's 2000 px shadow, so no huge layer; the spotlight and
  the card glide 0.45 s, cut with reduced motion. Opens by itself 1.5 s after the page when `tourSeen` is
  false; Done, Skip and Escape set it. Review hashes: `#tour=<1…5>`, `#menu`, `#menu=<param>`, `#about`;
  `#shot` never auto-opens the tour (so other tasks' headless shots are unchanged).
- **Texts**: steps 1–4 are the mockup's `TOUR` verbatim (step 4's "Drag inside the pictures" becomes true
  as T6.11/T6.12/T6.14 land). Step 5 until T4.2: "The macros move other controls. Point at one to light
  what it moves: a ring on a knob means something is moving it." (mine; the mockup's mentions the LFO,
  the envelope and Fire).
- **UiCheck**: `--size N`; the settings override; probes for the tour (auto-open on a clean file, the five
  spotlights, Next to Done, seen in the file, Tour button + Escape, menu + Skip), the menu (prevented
  default over the dome, items and tick, clamp in the corner, press outside, knob hint/Reset/Enter value
  landing, a choice's menu, About + Escape, compositing layers) and the sizes (S and L by click, M by the
  arrow key: editor size, file, inner size, every canvas re-fitted exactly, the tour walked at each).
  Result: PASSED, 0 unbound, dpr 1 (second display) and dpr 2 (built-in).
- **Tests**: `tests/unit/UiSettingsTests.cpp` (sizes, the opening size rule, the file round trip, the
  override); it needed one line in `tests/CMakeLists.txt` (outside the allowed paths, trivially).
- **Real editor**: a real right-click (a posted CGEvent) on the dome and on a knob showed only the page's

- **Merged with T6.9, T6.11, T6.12, T6.14 before landing**: ctest 141/141, UiCheck PASSED (0 unbound; the menu
