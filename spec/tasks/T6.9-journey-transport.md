## Goal
The header's static "Journey 24×" pill becomes a transport: run or freeze, the clock, the speed,
the recorded day, loop. All of it is saved with the session. Live stays for M5.

## What exists
- `SkyRuntime::setSpeed(modelSecondsPerSecond)` and `seek(utc)`: any thread, applied at the next
  block. Speed 0 is Freeze (the curtain keeps breathing). At the track's end model time holds.
- `SkyFeed::load(dayId, seed, params)`: message or data thread (it allocates); builds a
  `TrackBundle` and publishes it; the audio thread picks it up at the next block.
  `data::kSkyDays` lists the three bundled days. `SkyFeed::kDefaultJourneyStart` is the storm's start.
- `SkySound` handles a seek without a click (`SkyModel::seeks()`, `Exciter::rebase`, the harmony
  told the landing phase; T6.6).
- The page reaches the plug-in through native functions (`seek`, `uiReady` in `PluginEditor.cpp`;
  `WT.native(name, …)` in `bridge.js`; `WT_MOCK_NATIVE` in the mock).

## Design
- **State** (not automatable; `spec/03` §State): a `journey` child in the plug-in state with
  `day`, `speed` (the running speed), `frozen`, `loop`, `utc` (model time when saved). Owned by
  `PluginProcessor` (a small `JourneyState` struct beside `SkyFeed`); restored in
  `setStateInformation` (load the day, set the speed or 0, seek to `utc`). State version 2 → 3;
  a v2 state gets the defaults (storm day, 24×, running, no loop, the default start).
- **Native functions** (message thread): `journeySet({ frozen?, speed?, loop?, day? })`. Speed is
  one of 1, 24, 60, 240, 1440 (the owner may change the set; keep it in one table). `day` loads
  through `SkyFeed::load` and seeks to that day's start: the storm 17:20 UT on its first day, the
  other two as `source/ui/mock.js` `START` has them. Measure `load` on the message thread; if it
  takes over 50 ms, note it (a background thread comes with M5; do not add one here).
- **A new day must not click or swell.** The sound treats a newly picked-up track like a seek:
  re-base the exciter, tell the harmony the landing phase. If `SkyModel` does not already count a
  track change as a seek, make it do so and say so in the notes. Colours slew 2 s as always.
- **Loop:** when model time reaches the track's end and `loop` is on, seek to the track's start
  (the same click-free path). Loop off: hold there and report `ended` so the button shows Run
  again. Decide in the audio thread from atomics; no allocation, no lock.
- **Telemetry:** `sky.speed` and `sky.day` exist. Add `journey: { frozen, speed, loop, ended }` and
  send the day list once with the `day` event (`days: [{ id, label }]`).
- **UI** (mockup top bar): run/freeze button (icon swaps), the clock (`10 May 2024  17:30 UT`,
  fixed-width), a five-way speed segment, the day menu (three days; "Live sky" listed, disabled,
  "arrives with the data milestone"), a Loop chip. Do not bind the space bar: hosts use it.
  The Journey module in Details shows the same state read-only.
- **Mock:** `mock.js` implements `journeySet` on the sketch's model (`setSpeed`, reload a day).
