# T3.8 — Resonator bands: crossovers, tones, shift (engine)
**Milestone:** M3   **Depends on:** T3.7   **Branch:** feat/t3.8-resonator-bands
**Status:** approved by the owner, 2026-11-13.   **Read first:** `spec/09-ui-v2.md` §7, §9; `spec/05-sound-engine.md` §1, §3, §12, §14; mockup `#res`

Owner, 2026-11-13: "the resonators need to have a way of being tuned somehow separately"; "resonator
crossover frequencies that change the bands of colors … if dragged, one band gets elongated, while
the other one gets shorter."

## Goal
The four resonator bands (low, red, green, violet) share one pitch axis, divided by three
**crossovers** between a **floor** and a **ceiling**. Moving a crossover lengthens one band and
shortens its neighbour. Each band can also choose which chord tones it rings and be shifted
against the chord. 12-TET only (`00-vision` non-goal). This task is the engine and the
parameters; the display is T6.11.

## What exists
`dsp/Voicing`: `layerRange(layer, registerSemitones, spread)` gives fixed ranges (red 31–49,
green 50–74, violet 72–90 at Register 0, Spread 2); `layerSlots` gives fixed tone sets (red: root
and fifth; green: the chord; violet: the tones other than root and fifth); `nearestNote` folds a
pitch class into a range. `SkySound.cpp` voices a chord with them (line ~334). The low resonator
takes the chord's root (or the lowest held note) in the Sub or Bass octave (`low_octave`).
Register and Spread take effect only at the next chord change.

## Design
- **Parameters** (`parameters.yaml`, then `tools/gen_params.py`), group `bands`:
  | ID | Type | Range | Default | |
  |---|---|---|---|---|
  | `band_floor` | int (MIDI note) | 21 … 60 | 24 | lowest note of the low band |
  | `band_x1` | int | 28 … 84 | 36 | crossover low │ red |
  | `band_x2` | int | 33 … 96 | 50 | crossover red │ green |
  | `band_x3` | int | 38 … 103 | 73 | crossover green │ violet |
  | `band_ceiling` | int | 43 … 108 | 91 | first note above the violet band |
  | `band_blend` | float, st | 0 … 6 | 1.5 | how far neighbours reach into each other |
  | `red_tones`, `green_tones`, `violet_tones` | choice | Root, Root + fifth, Chord, Colours, All | Root + fifth, Chord, Colours | |
  | `red_shift`, `green_shift`, `violet_shift` | int, st | −12 … 12 | 0 | transpose the band against the chord |
  Band *k* spans notes [edge*ₖ*, edge*ₖ₊₁*). Minimum widths: low 12 st (so the root always has a
  place), the others 5 st. The engine enforces order and minimum widths whatever the host
  automates (clamp from the floor upward); the UI clamps while dragging.
  **Removed:** `register_semis`, `spread`, `low_octave` (moving all edges is Register; their
  spacing is Spread; the low band's place is Sub/Bass). Nothing has been released. State version
  bump; an older state loads with the band defaults.
- **Voicing** (`Voicing.h/.cpp`, header first): `BandEdges { floor, x1, x2, x3, ceiling; blend }`;
  `bandRange(BandEdges, Layer)` → `NoteRange` = the band's span widened by `round(blend)` on each
  inner side (never past the floor or ceiling); `bandSlots(Chord, TonesChoice, shiftSemitones)` →
  `Slots` (Root; Root + fifth; the chord padded as `layerSlots` green does; the colours with the
  same fallback as violet today; All = Chord). `layerRange` and `layerSlots` go when nothing calls them.
- **Low band:** the low resonator's note is the lowest note of the root's pitch class at or above
  `band_floor` (in Play mode: the lowest held note folded the same way). Its octave partial stays.
- **Applying a change:** a moved edge, tone choice or shift re-voices the current chord through the
  double-bank crossfade, the way a key change by hand does today, once the value has been still for
  300 ms (count it in ticks). No retune of ringing energy, no click. Play mode's voices keep their
  own partials; only the low note's folding follows the edges.
- **Telemetry:** `ChordState` already carries every voice's note per layer; add the five edges as
  they are applied, so the display can draw what the engine uses.
- **Goldens change on purpose.** The defaults give contiguous bands: red's floor moves from G1 (31)
  to C2 (36) and the low band takes C1–B1; green and violet keep 50–74 and 72–90 within the blend.
  Write the reason here and regenerate `tests/golden/sound`. Sky goldens must not change.

## Done
- **Voicing** (`dsp/Voicing`): `BandEdges` (floor, x1, x2, x3, ceiling, blend) with `clampEdges` (floor
  into 21–60; each edge at least 12 / 5 / 5 / 5 above the one below, clamped from the floor upward and
  never past its parameter maximum; blend 0–6), `bandRange` (the span widened by round(blend) on each
  inner side, never below the floor nor up to the ceiling), `lowNote`, `Tones` and `bandSlots` (Root;
  Root + fifth = red before; Chord = green before; Colours = violet before; All = Chord; a pitch-class
  shift), `Bands` and `clampBands`. `layerRange` and `layerSlots` are gone.
- **SkySound:** `Settings::bands` replaces `registerSemitones` and `spread`. A band change that has
  been still for 30 ticks (300 ms) becomes the applied bands (`bands()`); the current chord is then
  requested again (urgent) and voiced into the other bank through the usual 12 s crossfade; a chord
  already waiting is voiced with the new bands instead. A re-voice damps a still-ringing old bank to
  a T60 of **0.5 s** (`kRevoiceDampT60`) instead of the 3 s of other urgent changes, so the new voicing
  starts within 0.3 + 0.5 s; sky and MIDI changes are unchanged. When a band moved, each voice keeps its
  place within the band (old note mapped onto the new range) so an octave move does not fold all
  voices into one end; an unmoved band keeps every note. A blend move that keeps its rounding
  re-voices nothing. `bankBands(bank)` tells which bands a bank was voiced with.
- **Low band:** `LowResonator` takes a floor (`setFloor`) instead of an octave; its note is
  `lowNote(pc, floor)`, and the same note again (a floor move that keeps it) changes nothing.
  `Sources` reads the floor from SkySound's applied bands every tick (so it waits the same 300 ms), in
  drone and Play mode.
- **Parameters** (67 now): new group `bands`: `band_floor`, `band_x1`, `band_x2`, `band_x3`,
  `band_ceiling` (int, MIDI notes), `band_blend` (float, st), `red_tones`, `green_tones`,
  `violet_tones` (choice Root, Root + fifth, Chord, Colours, All), `red_shift`, `green_shift`,
  `violet_shift` (int, st). Removed `register_semis`, `spread`, `low_octave`. **State version 3**: a v2
  state loads with the default bands (the three old properties no longer bind; tested).
- **Telemetry:** `ChordState::edges` (int16 × 5: floor, x1, x2, x3, ceiling) and `ChordState::blend`,
  the bands the current bank was voiced with (in Play mode, the applied bands); the editor sends them
  as `chord.edges` and `chord.blend`. The chord is republished when the edges change.
- **UI (interim, until T6.11):** a **Bands** button in the Layers head (where Sub/Bass was) opens a
  small popover with plain controls: six knobs (Floor, Low|Red, Red|Grn, Grn|Vio, Ceiling, Blend, values
  as MIDI numbers) and per band a Tones segment row and a Shift knob. `#bands` in the URL opens it for
  screenshots. Register and Spread left the Harmony card. The mock voices in the bands, re-voices 300 ms
  after a band control moves and sends `edges`/`blend`; its low note folds from the floor.
- **Render tool:** `--sweep id=from:to[:t0:t1]` (a straight line on a 0.1 s grid, blocks cut at the
  grid, so the same sweep lands on the same samples at any `--block`); the `--sky` path takes
  `--edges f,x1,x2,x3,c` and `--blend` instead of `--register` / `--spread`.
- **Spec:** `05` §1, §3, §12 (note), §14, the diagram, and a new §16 (the bands).

## Notes / open questions
- For the owner's ear: the default edges, the default blend, whether Low should stay in the chain.
  Also: whether a re-voice should crossfade over the full 12 s (it does now, like a key change by hand;
  the new voicing starts at once but takes a few seconds to bloom) or faster for band moves.
- The shift is a pitch-class shift (as in the mockup's `toneSet`): ±12 equals 0, because the band's
  range sets the octave. Moving the band is how to move an octave.
- A band narrower than an octave still rings every tone of its set: `nearestNote` keeps the band's
  bottom and lets a tone sit up to 11 semitones above it (as the old narrow ranges did), so such a band
  may reach into its upper neighbour. The minimum widths (5) are the spec's.
- `band_x1`'s parameter minimum (28) is below what the default floor allows (floor + 12 = 33 at the
  lowest floor, 36 at the default): values under floor + 12 clamp. The ranges are the spec's.
- Hosts show the edges as MIDI numbers (the generator has no note-name formatter; `tools/gen_params.py`
  is outside this task). The interim popover shows numbers too; T6.11 draws them.
- A floor move also re-voices the bank (the edges differ), although the bank's notes only change when
  the floor pushes the crossovers up; harmless (a crossfade to the same notes).
- Build note: the disk was full (≈ 90 MB free) when this task started; the worktree's `build/dev` is
  configured with a compiler launcher that appends `-g0` (`build/nodebug.sh`), so its objects carry no
  debug info (607 MB instead of ≈ 2.3 GB). Flags, warnings and the Debug configuration are otherwise
  the preset's.
