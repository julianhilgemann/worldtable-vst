# T2.2 — The slow sky in C++
**Milestone:** M2   **Depends on:** T2.1   **Branch:** feat/t2.2-slow-sky

## Goal
Port the sketch's slow sky to C++ and build `SkyTimeline` with it. The slow
sky runs on model time with a fixed 1 s grid: data, reservoir, substorm phases,
activity, oval, assimilation and magnetic local time. Done when the C++
timeline reproduces the 10 May 2024 goldens.

## Why the plan's cut changed
`spec/07` split M2 into reservoir and phases (T2.2), curtain (T2.3),
assimilation, RNG and track reading (T2.4) and observer and astronomy (T2.5).
The sketch's `slowStep` needs all of these at once: phases need the seeded
RNG and MLT, MLT needs the sun's position and the geomagnetic frame, and the
goldens test the slow sky as a whole. So T2.2 takes everything the slow step
uses, and the later tasks shrink (`spec/07` updated):
- T2.3: `SkyModel` (step, seek, speed, snapshot), curtain, pulsations,
  whistlers, events.
- T2.4: determinism and block-size tests, hand-offs (ADR-0003), running in
  `processBlock`.
- T2.5: moon, projection (az/el, magnetic zenith), snapshot astronomy and
  observer.

## Design
- **Line by line from `prototype/sky/`.** Same names, same order of
  operations, `double` throughout, so differences come only from the
  `float` track and from libm.
- `source/sky/SkyRandom.h`: `rng.js` (hash32, rand01, randS, noise1, noise2,
  fbm2) with `uint32_t` arithmetic: bit-identical to the sketch.
- `source/sky/Astronomy.{h,cpp}`: `astro.js` for the sun (NOAA formulas),
  GMST, alt/az and the subsolar point. The moon comes in T2.5.
- `source/sky/Observer.{h,cpp}`: the centred-dipole frame from `observer.js`:
  geographic → geomagnetic, the station's mlat/mlon, MLT. Projection: T2.5.
- `source/sky/SlowSky.{h,cpp}`: `initialSlowState()` and `slowStep()`, the
  sketch's `initialSlow` and `slowStep`. Internal, not a protected interface.
  Events go into a caller's fixed buffer (at most 2 per step), so `slowStep`
  can run on the audio thread in T2.3.
- `source/sky/SkyTimeline.cpp`: `SkyTimeline::build` and
  `checkpointAtOrBefore` (declared in `SkyModel.h`, T2.1).
- `source/data/TrackBuilder.{h,cpp}`: `parseTrackJson` (a `track.json` from
  `resources/sky/` → `RawTrack`) and `prepareTrack` (`data.js`: gap fill,
  valid flags, quiet baseline → `WorldSnapshot`). This is the pure part of
  M5's TrackBuilder, without network.
- New `.cpp` files join `WorldtableShared`, so the plug-in compiles them with
  its warnings. Nothing in `processBlock` calls them yet.

## Scope
The files above, their unit tests, and `tests/unit/SkyGoldenTests.cpp`
(2024-05-10, seed 1).

## Out of scope

## Acceptance criteria
- [x] `SkyRandom` equals the sketch's values at sample points (hash and
      draws bit-identical; noise within 1e-14).
- [x] Sun position, subsolar point, CMO's mlat/mlon and MLT match the sketch at
      sample times (within 1e-9 relative; GMST within 1e-8°, see Notes).
- [x] `prepareTrack` matches `data.js`: the quiet baseline for 2024-05-10
      (bit-identical), a short gap (interpolated) and a long gap (decay toward
      climatology).
- [x] Goldens (2024-05-10, seed 1): the eight slow channels match per minute
      within a stated tolerance; the phase matches in ≥ 99.9 % of minutes; all
      24 onsets match in kind, time (± 1 min) and strength (± 1 %).
- [x] `SkyTimeline`: 2,881 states for 48 h, `checkpointAtOrBefore` clamps at
      both ends, its onsets are the goldens' onsets; build time measured.
- [x] `slowStep` doesn't allocate (6 h of steps, counted per thread).
- [x] `ctest` green (36/36); the plug-in builds with no new warnings;
      pluginval strictness 8 passes.

## Notes
- **Goldens, 2024-05-10, seed 1** (max |C++ − sketch| over 2,880 minutes):
  energy 5.0e-5, activity 5.0e-5, gain 5.0e-5, unloading 5.0e-5, coupling
  5.1e-5, arc latitude 5.3e-5, ΔH model 1.5e-4 nT. The goldens are rounded to
  1e-4, so 5e-5 is the floor: the port matches to the goldens' precision.
  The phase matches in all 2,880 minutes; all 24 onsets match in kind, time and
  strength. Tolerances in `SkyGoldenTests.cpp`: 1e-4 (ΔH model 1e-3 nT).
- **Replaying from a checkpoint is bit-identical** to the straight run
  (`memcmp` of the state after 60 steps): what `seek()` needs in T2.3.
- **Build time:** `SkyTimeline::build` for 48 h (172,800 slow steps) takes
  130 ms in a Debug build on this arm64 Mac, within the 0.2 s that T2.1 estimated.
- **FMA:** clang contracts `a + b * c` into fused multiply-adds, V8 doesn't, so
  some results differ from the sketch in the last bits (GMST by 5e-10° at
  3.2e6° before the wrap). Within one build everything stays deterministic.
  An MSVC build may differ in the same last bits; the goldens' tolerances
  cover it.
- `slowStep` takes the seed as an argument: `SlowSkyState` (T2.1) has no seed
  field, the timeline and the model own it.
- `tests/unit/AllocationCounter.cpp` replaces global `operator new` in the test
  binary and counts per thread; T2.3 will use it for `step()`.
- `build/dev` now has `WORLDTABLE_COPY_PLUGINS=OFF`, so dev builds no longer
  overwrite the installed Release plug-in (handover gotcha).
